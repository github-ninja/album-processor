# Album Processor

[![Tests](https://github.com/github-ninja/album-processor/actions/workflows/tests.yml/badge.svg)](https://github.com/github-ninja/album-processor/actions/workflows/tests.yml)
![Python 3.13](https://img.shields.io/badge/python-3.13-blue)
[![License: MIT](https://img.shields.io/badge/license-MIT-green)](LICENSE)

*[English version](README.md)*

Telegram-бот для своего сервера: превращает всё, что попало в папку загрузок,
в аккуратную FLAC-медиатеку — с названиями, тегами и обложками по
[Discogs](https://www.discogs.com), с ReplayGain, с проверкой на поддельный
lossless — и потом поддерживает в ней порядок.

Кладёте альбом в `downloads/`, отправляете боту `/newalbum` — и через минуту он
лежит в `music/Исполнитель/ГГГГ - Альбом/` так, как вы разложили бы его руками.
Сделан под [Navidrome](https://www.navidrome.org) и foobar2000, подходит для
любого плеера, который читает теги.

> Бот общается по-русски; код, логи и английская документация — на английском.

## Возможности

**Импорт**
- Находит новые альбомы в загрузках: `Альбом/`, `Исполнитель/Альбом/`, многодисковые —
  в подпапках `CD1/`, `CD2/`… или одной папкой с номерами дисков в тегах.
- Режет образ альбома (один файл FLAC/APE/WAV/ALAC + CUE) на треки с точностью
  до сэмпла по меткам `INDEX 01`; CUE в UTF-8, UTF-16 или cp1251; несколько
  образов в одной папке становятся отдельными дисками.
- Приводит ALAC, APE, WAV и хайрез-FLAC к FLAC 16 бит / 44.1 кГц (ресемплер soxr VHQ,
  TPDF-дизер); источник 16/44.1 копируется бит-в-бит.
- Распознаёт апконверты из lossy в lossless по спектру (срез MP3/AAC) и
  спрашивает, что делать, — со спектрограммой и кнопками *Обработать / Оставить / Удалить*.
- Удаляет всё, что не музыка (логи, CUE, сканы, плейлисты), и пустые папки.

**Метаданные из Discogs**
- Название альбома — по *мастер-релизу* Discogs, год — *оригинального* издания,
  жанры — по стилям Discogs.
- Имена исполнителей — как у сущности в Discogs («VIMES» → «Vimes»); псевдонимы
  учитываются, если с ними согласны теги треков («Carl Finlow» из магазина → «Silicon Scally»).
- Защита от ложных совпадений: релиз, чей трек-лист не пересекается с файлами
  (альбом группы-тёзки), отбрасывается.
- Другая версия альбома — *Instrumentals*, *Remixes* — остаётся отдельным альбомом,
  даже если Discogs записал её изданием оригинала.
- Чистит неряшливые имена папок: `2013-09-02 - I Am Legion [GB - DVSNCD003] (FLAC 24-96)` → `I Am Legion`.

**Исполнители трека**
- Несколько исполнителей — отдельные значения тега (multi-value), в именах
  файлов — «A», «A & B», «A, B & C».
- Приглашённые гости — исполнители трека, а не часть названия:
  `The Universe (feat. Jennifer Neal)` → исполнители *A Guy Called Gerald; Jennifer Neal*.
- Ремиксеры — не исполнители: «(X Remix)» остаётся в названии, а X попадает в `REMIXER`.
- Распутывает записи магазинов: строку для показа рядом с гостями
  (`["Noisia & Camo & Krooked", "Camo & Krooked"]`), совместных исполнителей
  одной строкой (`"Noisia, Calyx & TeeBee"`), дубли в разном написании («J P Cooper» / «JP Cooper»).

**Какие теги пишутся**
- Исполнитель, название, альбом, исполнитель альбома, год, жанр, номера и количество треков и дисков.
- `RELEASETYPE` (album / ep / single + compilation, soundtrack, dj-mix, remix) —
  по нему Navidrome делит страницу исполнителя на разделы; `COMPILATION=1` для Various Artists.
- ReplayGain 2.0: поправки трека и альбома (EBU R128, −18 LUFS) с **истинными**
  пиками — защита плеера от клиппинга учитывает и пики между сэмплами.
- Больше ничего: ни комментариев, ни текстов песен, ни мусора из источника.

**Обложки**
- `Cover.jpg` 1000×1000 JPEG, та же картинка встроена в каждый трек.
- Берётся с Deezer, если там есть именно этот альбом, иначе своя из загрузки;
  никогда не растягивается; маленькая обложка заменяется, только если на Deezer
  есть та же картинка крупнее.

**Обслуживание медиатеки — `/fixlibrary`**
- Сверяет каждый альбом с правилами и показывает план, ничего не трогая:
  применить всё, пройти по одному или отменить.
- Исправляет имена, гигиену тегов (невидимые символы, написание жанров, количество треков),
  написание исполнителей по всей медиатеке, обложки, формат звука,
  недостающие ReplayGain и типы релизов, дубли (тот же альбом с другим годом или регистром).
- `/fixlibrary all` вдобавок перепроверяет названия всех альбомов по Discogs.

**Безопасность**
- Один пользователь: бот игнорирует всех, кроме `ALLOWED_ID`.
- Из медиатеки ничего не удаляется: заменённые альбомы и обложки переносятся в
  `music/.album_processor/replaced/`, каждое изменение записывается в журнал со старыми значениями.
- Файл заменяется только после того, как новая версия записана и проверена
  (конвертация, нарезка по CUE, теги).

## Как это работает

Для каждого альбома в папке загрузок:

1. **Нарезка** образа по CUE; **конвертация** ALAC, APE, WAV и хайреза во FLAC 16/44.1.
2. **Проверка на апконверт** — срез спектра каждого трека; подозрительный
   MP3→FLAC откладывается до вашего решения (`UPCONVERT_ACTION`).
3. **Опознание** — исполнитель и название из папки и тегов, поиск в Discogs
   (название, оригинальный год, жанр, трек-лист, роли, тип релиза), совпадение проверяется по файлам.
4. **Обложка** — с Deezer или своя из загрузки, приведённая к стандарту и встроенная.
5. **Уборка** — удаление всего, что не музыка.
6. **Теги и имена** каждого трека: `NN. Исполнитель - Название.flac`, исполнители разобраны.
7. **ReplayGain** — громкость каждого трека и альбома (треки меряются параллельно).
8. **Перенос** в `music/<Исполнитель альбома>/<ГГГГ - Альбом>/`; старая копия того же альбома отодвигается.

Бот только запускает `album_processor.py` и разговаривает с вами; всю работу
делает пакет `albumproc`, которым можно пользоваться и из командной строки.

## Устройство медиатеки

```
music/
├── Noisia/
│   ├── 2010 - Split The Atom/
│   │   ├── 01. Noisia - Split The Atom.flac
│   │   ├── …
│   │   └── Cover.jpg
│   └── 2013 - Hyenas, The Liquid/          ← совместный релиз: папка первого исполнителя
├── Some Artist/
│   └── 2001 - Double Album/
│       ├── CD1/ …                          ← многодисковые альбомы
│       ├── CD2/ …
│       └── Cover.jpg
└── .album_processor/                       ← журнал и заменённые файлы (плееры её не видят)
```

- Папка альбома: `ГГГГ - Альбом` с оригинальным годом; недопустимые в именах файлов символы заменяются.
- Папка исполнителя: первый указанный исполнитель альбома («Noisia; Mayhem» → `Noisia/`);
  дуэт со своей страницей в Discogs получает свою папку (`Fred V & Grafix/`).
- Источник истины — теги: имена файлов и папок выводятся из них.

## Быстрый старт

Нужны Docker, токен Telegram-бота и ваш Telegram ID.

1. **Создайте бота** у [@BotFather](https://t.me/BotFather) (`/newbot`) и скопируйте токен.
2. **Узнайте свой ID**, например у [@userinfobot](https://t.me/userinfobot).
3. *(Необязательно)* **Создайте токен Discogs** на
   [discogs.com/settings/developers](https://www.discogs.com/settings/developers):
   лимит вырастет с 25 до 60 запросов в минуту.
4. **Скачайте код и настройте:**
   ```sh
   git clone https://github.com/github-ninja/album-processor.git
   cd album-processor
   cp .env.example .env
   nano .env        # BOT_TOKEN, ALLOWED_ID, DOWNLOADS_DIR, MUSIC_DIR
   ```
   В `docker-compose.yml` укажите в `user:` uid:gid владельца папок с музыкой (`id -u`, `id -g`).
5. **Запустите:**
   ```sh
   docker compose up -d --build
   docker compose logs -f        # "Bot started. Waiting for commands…"
   ```
6. Отправьте боту `/help`.

Обновление: `git pull && docker compose up -d --build`.

### Настройки

| Переменная | Обязательна | По умолчанию | Смысл |
|---|---|---|---|
| `BOT_TOKEN` | да | — | Токен Telegram-бота |
| `ALLOWED_ID` | да | — | Единственный Telegram ID, которому бот отвечает |
| `DOWNLOADS_PATH` | | `/mnt/data/downloads` | Папка загрузок внутри контейнера |
| `MUSIC_PATH` | | `/mnt/data/music` | Папка медиатеки внутри контейнера |
| `DISCOGS_TOKEN` | | — | Личный токен Discogs (выше лимит запросов) |
| `UPCONVERT_ACTION` | | `ask` | Подозрение на апконверт: `ask` (спросить), `warn` (обработать всё равно), `skip` (оставить в загрузках) |
| `TZ` | | UTC | Часовой пояс для логов |

`docker-compose.yml` монтирует `DOWNLOADS_DIR` и `MUSIC_DIR` из `.env` в
`/downloads` и `/music` и сам выставляет оба пути.

## Использование

### Команды бота

| Команда | Что делает |
|---|---|
| `/newalbum` | Обработать все новые альбомы из загрузок и прислать отчёт. |
| `/fixlibrary` | Проверить медиатеку, показать план; применить всё, по одному или отменить. |
| `/fixlibrary all` | То же плюс сверка названий всех альбомов с Discogs (долго: лимит Discogs). |
| `/help` | Список команд. |

### Командная строка

Тот же движок без Telegram, например через `docker compose exec album-processor …`:

```sh
python album_processor.py                       # обработать все новые альбомы
python album_processor.py "<папка альбома>"…    # обработать указанные папки
python album_processor.py --fix-library [--all] --plan-out plan.json   # проверить, сохранить план
python album_processor.py --fix-library --apply plan.json              # применить (проверенный) план
```

### Если что-то пошло не так

- `music/.album_processor/fixes.jsonl` — каждое изменение медиатеки со старыми значениями.
- `music/.album_processor/replaced/<запуск>/` — заменённые альбомы и обложки.

## Разработка

Структура кода, тесты и зависимости описаны в [английской версии](README.md#development).
Коротко:

```sh
cd scripts
pip install -r requirements.txt
python -B -m unittest discover -s tests -t .
```

`requirements.in` — прямые зависимости; `requirements.txt` фиксирует всё дерево
версий для воспроизводимой установки (образ Docker, CI). Обновление: поставить
`requirements.in` в чистое окружение, прогнать тесты, `pip freeze > requirements.txt`.

## Ограничения

- Один пользователь на бота; одна обработка за раз.
- Бот с характером: медиатека — FLAC 16/44.1 по правилам выше; lossy-файлы
  принимаются как есть, но не конвертируются и не улучшаются.
- Метаданные — из Discogs: альбом, которого нет в Discogs, сохраняет название
  папки, теги и год из загрузки.
- Discogs разрешает 25 (с токеном — 60) запросов в минуту; полная
  `/fixlibrary all` на большой медиатеке идёт долго.
